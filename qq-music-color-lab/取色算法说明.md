# 取色算法说明

> 基于 OKLab / OKLCH 的专辑封面主题色提取与柔和双色背景生成方案。

## 1. 设计目标

该算法用于从专辑封面中提取主题颜色并生成协调的播放器界面配色：

- 从专辑封面中提取一个主题主色和一个辅助色；
- 主色用于生成歌词、播放按钮、进度条等强调色；
- 主色和辅助色分别生成高明度、低刺激的背景色；
- 两个背景色之间通过感知均匀的桥接色自然过渡；
- 尽量保持封面原始色相，只调整明度和色度。

处理链路如下：

```text
上传图片
  ↓
128 × 128 居中裁切采样
  ↓
sRGB → Linear RGB → OKLab → OKLCH
  ↓
16 色 OKLab K-means 聚类
  ↓
OKLCH 综合评分选择主色
  ↓
面积 × 色度 × 感知距离选择第二色
  ↓
生成强调色、背景主色、背景第二色
  ↓
在 OKLab 中混合桥接色
  ↓
三层模糊径向渐变渲染
```

---

## 2. 为什么使用 OKLab / OKLCH

### 2.1 OKLab

OKLab 是接近人眼感知均匀的颜色空间：

- `L` 表示感知明度；
- `a` 表示绿—红方向；
- `b` 表示蓝—黄方向。

在 OKLab 中计算欧氏距离，比直接计算 RGB 距离更接近人眼看到的色差：

```text
ΔE = √[(L₁-L₂)² + (a₁-a₂)² + (b₁-b₂)²]
```

该算法使用此距离完成：

- K-means 聚类；
- 第二色与主色的感知距离计算；
- 桥接色混合。

### 2.2 OKLCH

OKLCH 是 OKLab 的圆柱坐标表达：

```text
L = 感知明度
C = 色度
H = 色相角
```

转换关系：

```text
C = √(a² + b²)
H = atan2(b, a)

a = C × cos(H)
b = C × sin(H)
```

OKLCH 适合主题色生成，因为可以分别控制：

- 颜色有多亮；
- 颜色有多鲜艳；
- 是否保留原始色相。

## 3. 图片采样

### 3.1 缩放尺寸

图片上传后先绘制到 `128 × 128` Canvas：

```js
const size = 128;
```

缩小图片的作用：

- 降低浏览器计算量；
- 弱化纹理、噪声和压缩细节；
- 保留足够的小面积候选色；
- 让不同分辨率的封面使用统一输入规模。

### 3.2 居中裁切

图片使用类似 `object-fit: cover` 的方式铺满正方形：

```js
scale = max(128 / imageWidth, 128 / imageHeight)
```

超出正方形的部分从两侧或上下居中裁掉。

### 3.3 像素过滤

读取像素时：

- Alpha 小于 `160` 的像素直接忽略；
- 优先排除 OKLCH 明度低于 `0.055` 或高于 `0.975` 的极端像素；
- 如果过滤后剩余像素少于原像素的 `28%`，则退回使用全部非透明像素。

这样可以减少纯黑、纯白、透明边缘对聚类的影响，同时避免极端封面因过滤过多而无法计算。

---

## 4. 16 色 OKLab K-means 聚类

采样像素被聚类为最多 16 个候选颜色：

```js
kMeans(points, 16, 16)
```

参数含义：

| 参数 | 数值 | 说明 |
|---|---:|---|
| 聚类数量 `K` | 16 | 保留较小但有意义的辅助颜色 |
| 迭代次数 | 16 | 在浏览器性能和收敛稳定性之间折中 |
| 最小聚类占比 | 0.2% | 更小的颜色簇作为噪声过滤 |

### 4.1 初始中心

第一个中心从高色度像素中选取。后续中心使用“离已有中心较远，同时具有一定色度”的像素：

```text
初始化权重 = 到最近中心的 OKLab 距离
            × [0.35 + min(C / 0.18, 1)]
```

与随机初始化相比，这种方式更容易获得稳定且分散的候选颜色。

### 4.2 聚类输出

每个候选色包含：

```js
{
  lab,    // OKLab 坐标
  lch,    // OKLCH 坐标
  rgb,    // 用于界面显示
  ratio   // 在有效像素中的面积占比
}
```

## 5. 主色选择规则

### 5.1 候选过滤

主色和第二色优先从满足以下条件的颜色簇中选择：

```text
ratio ≥ 0.002
0.12 ≤ L ≤ 0.94
C ≥ 0.008
```

即：

- 至少占有效像素的 `0.2%`；
- 不是极黑或极白；
- 具有最基本的色彩倾向。

若过滤后少于两个候选，则退回使用所有聚类结果。

### 5.2 主色评分公式

每个候选色的主色评分为：

```text
PrimaryScore = AreaScore × ChromaScore × LightnessScore
```

#### 面积得分

```text
AreaScore = ratio^0.58
```

面积越大越重要，但指数小于 1，避免最大色块完全压制其他更有表现力的颜色。

#### 色度得分

```text
ChromaScore = 0.35 + min(C / 0.16, 1.25)
```

色度越高，越可能成为界面主题色。基础值 `0.35` 保证低彩封面仍然可选出颜色。

#### 明度得分

```text
LightnessScore = 0.35 + exp[-((L - 0.62) / 0.27)²]
```

这是以 `L = 0.62` 为中心的高斯型权重：

- 中等明度颜色权重较高；
- 过暗区域通常是阴影或黑底；
- 过亮区域通常是白底、高光或浅色留白。

最终选择 `PrimaryScore` 最大的候选色作为主色。

---

## 6. 第二色选择规则

第二色不是简单选择面积第二大的聚类，而是综合考虑：

- 面积；
- 色度；
- 与主色的感知距离；
- 明度可用性。

评分公式：

```text
SecondaryScore = AreaScore
               × ChromaScore
               × DistanceScore
               × LightnessScore
```

### 6.1 面积得分

```text
AreaScore = ratio^0.46
```

第二色的面积指数比主色更低，允许小面积但有明确辨识度的颜色进入候选。

### 6.2 色度得分

```text
ChromaScore = 0.30 + min(C / 0.14, 1.20)
```

### 6.3 感知距离得分

```text
ΔE = OKLabDistance(candidate, primary)

DistanceScore = 0.35 + min(ΔE / 0.26, 1.45)
```

第二色需要与主色有一定区分，但不会强制选择互补色或最远颜色。

候选的最低距离为：

```text
ΔE ≥ 0.045
```

### 6.4 明度得分

```text
LightnessScore = 0.5
               + 0.5 × exp[-((L - 0.66) / 0.32)²]
```

第二色适当偏向中高明度，方便后续生成柔和背景。

---

## 7. 第二色兜底

如果没有候选色满足最低感知距离，则生成与主色同色相的兜底色：

```text
L_fallback = clamp(L_primary + 0.08, 0.36, 0.90)
C_fallback = max(C_primary × 0.55, 0.018)
H_fallback = H_primary
```

因此单色封面最终会得到同色系的深浅背景，而不是凭空出现另一种色相。

---

## 8. 强调色计算

强调色用于：

- 歌词高亮；
- 播放按钮；
- 进度条；
- 上传图标等状态元素。

### 8.1 强调色明度

```text
L_accent = clamp[
  0.58 + (L_primary - 0.58) × 0.22,
  0.54,
  0.66
]
```

该公式会压缩原始主色明度变化，使强调色稳定落在适合浅色背景的中等明度范围。

### 8.2 强调色色度

```text
C_accent = clamp(
  C_primary × 1.28 + 0.025,
  0.09,
  0.21
)
```

作用：

- 提升低彩主色的辨识度；
- 保留高彩封面的主题感；
- 通过上限避免颜色过度刺眼。

### 8.3 强调色色相

```text
H_accent = H_primary
```

强调色保留主色的原始色相。

---

## 9. 背景主色计算

背景主色是主色的高明度、低色度版本。

### 9.1 明度

```text
L_bg_primary = clamp[
  0.87 + (L_primary - 0.50) × 0.035,
  0.86,
  0.90
]
```

原始颜色只对背景明度产生轻微影响，最终基本稳定在柔和浅色范围。

### 9.2 色度

```text
C_bg_primary = clamp(
  C_primary × 0.48,
  0.022,
  0.085
)
```

### 9.3 色相

```text
H_bg_primary = H_primary
```

---

## 10. 背景第二色计算

背景第二色使用第二候选色的原始色相，同样只调整明度与色度。

### 10.1 明度

```text
L_bg_secondary = clamp[
  0.90 + (L_secondary - 0.50) × 0.025,
  0.89,
  0.93
]
```

第二背景色通常略亮于背景主色。

### 10.2 色度

```text
C_bg_secondary = clamp(
  C_secondary × 0.44,
  0.018,
  0.075
)
```

### 10.3 色相

```text
H_bg_secondary = H_secondary
```

---

## 11. 桥接色计算

背景不是只使用两种颜色，还会生成一个隐藏的桥接色作为底层。

### 11.1 OKLab 加权混合

先将两个背景色转换回 OKLab：

```text
Lab_bridge = Lab_bg_primary × 0.56
           + Lab_bg_secondary × 0.44
```

主色权重略高，因此中央过渡更靠近主题主色。

### 11.2 桥接色规整

将混合结果转为 OKLCH 后：

```text
L_bridge = clamp(L_mix + 0.012, 0.86, 0.93)
C_bridge = C_mix × 0.80
H_bridge = H_mix
```

桥接色略微提亮并降低 20% 色度，避免两个背景色混合后在中央形成过强色块。

桥接色统一使用上述 OKLab 加权混合和 OKLCH 规整公式。

---

## 12. 色域映射

部分高色度 OKLCH 颜色无法在 sRGB 屏幕中显示，因此使用渐进式降色度方式映射到可显示色域：

```text
最多尝试 24 次：
  如果 RGB 三通道均在 0～255，则返回
  否则 C = C × 0.91
```

若仍无法进入 sRGB 色域，则将色度降为 0，返回同明度的中性色。

这个过程保证最终输出始终是合法的 RGB / HEX 颜色。

---

## 13. 背景渲染方式

背景使用三层结构模拟大范围柔和色彩过渡：

```text
底层：桥接色
左下色团：背景主色
右上色团：背景第二色
```

### 13.1 主色色团

```css
radial-gradient(
  ellipse 88% 86% at 4% 96%,
  var(--bg-a) 0%,
  var(--bg-a) 20%,
  半透明主色 49%,
  transparent 78%
)
```

### 13.2 第二色色团

```css
radial-gradient(
  ellipse 150% 62% at 80% -4%,
  var(--bg-b) 0%,
  var(--bg-b) 27%,
  半透明第二色 62%,
  transparent 90%
)
```

### 13.3 模糊

默认参数：

```text
blur = 88px
strength = 100%
```

色团元素扩大到容器之外再进行模糊，避免边缘出现明显的透明衰减线。

## 14. 完整伪代码

```js
function extractTheme(image) {
  const pixels = sampleToCanvas(image, 128, 128)
    .filter(alpha >= 160);

  const preferredPixels = pixels.filter(pixel => {
    const [L] = toOKLCH(pixel);
    return L > 0.055 && L < 0.975;
  });

  const input = preferredPixels.length > pixels.length * 0.28
    ? preferredPixels
    : pixels;

  const clusters = kMeansInOKLab(input, {
    colors: 16,
    iterations: 16,
    minRatio: 0.002
  });

  const primary = maxBy(clusters, cluster =>
    pow(cluster.ratio, 0.58)
    * (0.35 + min(cluster.C / 0.16, 1.25))
    * (0.35 + exp(-pow((cluster.L - 0.62) / 0.27, 2)))
  );

  const secondary = maxBy(
    clusters.filter(cluster => deltaE(cluster, primary) >= 0.045),
    cluster =>
      pow(cluster.ratio, 0.46)
      * (0.30 + min(cluster.C / 0.14, 1.20))
      * (0.35 + min(deltaE(cluster, primary) / 0.26, 1.45))
      * (0.50 + 0.50 * exp(-pow((cluster.L - 0.66) / 0.32, 2)))
  ) || sameHueFallback(primary);

  const accent = toSRGB({
    L: clamp(0.58 + (primary.L - 0.58) * 0.22, 0.54, 0.66),
    C: clamp(primary.C * 1.28 + 0.025, 0.09, 0.21),
    H: primary.H
  });

  const bgPrimary = toSRGB({
    L: clamp(0.87 + (primary.L - 0.50) * 0.035, 0.86, 0.90),
    C: clamp(primary.C * 0.48, 0.022, 0.085),
    H: primary.H
  });

  const bgSecondary = toSRGB({
    L: clamp(0.90 + (secondary.L - 0.50) * 0.025, 0.89, 0.93),
    C: clamp(secondary.C * 0.44, 0.018, 0.075),
    H: secondary.H
  });

  const bridgeLab = mixOKLab(bgPrimary, bgSecondary, 0.56, 0.44);
  const bridgeLch = toOKLCH(bridgeLab);
  const bgBridge = toSRGB({
    L: clamp(bridgeLch.L + 0.012, 0.86, 0.93),
    C: bridgeLch.C * 0.80,
    H: bridgeLch.H
  });

  return { accent, bgPrimary, bgSecondary, bgBridge };
}
```

## 15. 参数汇总

| 环节 | 参数 |
|---|---|
| Canvas 采样 | `128 × 128` |
| Alpha 阈值 | `160` |
| 优先明度范围 | `0.055 < L < 0.975` |
| 过滤后最低像素占比 | `28%` |
| 聚类数量 | `16` |
| 聚类迭代 | `16` |
| 最小聚类面积 | `0.2%` |
| 主色最佳明度中心 | `L = 0.62` |
| 第二色最佳明度中心 | `L = 0.66` |
| 第二色最低 OKLab 距离 | `0.045` |
| 强调色明度 | `0.54～0.66` |
| 强调色色度 | `0.09～0.21` |
| 背景主色明度 | `0.86～0.90` |
| 背景主色色度 | `0.022～0.085` |
| 背景第二色明度 | `0.89～0.93` |
| 背景第二色色度 | `0.018～0.075` |
| 桥接混合权重 | 主色 `56%`，第二色 `44%` |
| 桥接色度衰减 | `80%` |
| sRGB 色域回退 | 每次 `C × 0.91`，最多 24 次 |
| 默认模糊 | `88px` |

## 16. 算法边界与后续优化

### 当前边界

1. **不考虑像素空间位置**  
   同样的颜色面积，无论位于封面中心还是角落，目前权重相同。

2. **不识别人脸、文字和 Logo**  
   算法只分析颜色，不理解图像语义。

3. **第二色由封面候选色决定**  
   如果封面本身色相单一，第二色可能与主色同属一个色系。

4. **强调色不保证文字无障碍对比度**  
   强调色主要用于大按钮、歌词高亮和进度状态；若用于小字号文本，需要额外进行 WCAG 对比度校验。

5. **K-means 仍可能受局部大色块影响**  
   极端构图下，面积较大的背景颜色可能压过人物或主体颜色。

### 可选优化方向

- 加入中心区域、边缘区域和四象限的空间权重；
- 使用显著性检测区分主体与背景；
- 对文字、Logo、小型高彩装饰做连通域过滤；
- 将固定参数通过更多真实截图拟合成可配置参数；
- 为强调色增加对比度约束与自动深浅调整；
- 输出 OKLCH、RGB、HEX 以及 CSS 变量代码。

---

## 17. 总结

取色算法的核心原则可以概括为：

> 先在 OKLab 中把封面归纳为有限的候选颜色，再在 OKLCH 中通过面积、色度和明度选择主色，通过感知距离选择第二色；所有主题色保持原始色相，只调整明度和色度，最后在 OKLab 中生成自然的桥接色。
